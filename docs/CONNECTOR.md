# Собственный Svacer Triage Connector

`app/triage_connector` — независимая реализация интеграции приложения с публичным
REST API Svacer. Лицензия собственного кода — MIT из корня проекта. Здесь нет
импорта, динамической загрузки или установки исходников пакета `svacer_mcp`.
Это замена транспортного слоя, а не переписывание интерфейса, очереди или правил
принятия решений. Сам сервер Svacer и доступ к Public API по-прежнему нужны.

## Основания реализации

Реализация создана по открытым описаниям протоколов и собственным вызывающим
модулям приложения. Исходники стороннего коннектора не использовались как шаблон.
Это описание происхождения нового кода, а не юридическое заключение о правах
на весь проект, сервер, товарные знаки или зависимости.

- [Svacer Public API](https://svacer.ispras.ru/mediawiki/index.php?title=Help:Public_API)
- [Формат разметки, экспорт и импорт](https://svacer.ispras.ru/mediawiki/index.php?title=Markup2)
- [Публичный контракт MCP-инструментов](https://svacer.ispras.ru/mediawiki/index.php?title=Help:13-alpha_MCP)
- OpenAPI установленного сервера: `/api/public/swagger/swagger.yaml` (сверено
  21.09.2026 без авторизации; копия рабочих настроек или схемы в репозиторий не включена).
- [MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk)
- Собственные контракты `triage_dashboard.py`, `codex_run.py`, `triage_queue.py`
  и `CODEX_TASK.md`.

## Совместимость

| Инструмент | Реализация |
| --- | --- |
| `get_projects`, `get_snapshots` | Список проектов, веток, снимков через Public API |
| `get_markers`, `get_warnings` | Полная scoped-выборка, фильтры, трассы, история, счётчики и поля |
| `get_project_stats` | Агрегация полной выборки по детектору и ручной разметке |
| `get_project_groups` | Документированная операция чтения группы |
| `get_diff` | Сравнение снимков, лимит на каждую категорию отдельно |
| `get_advanced_file_preview` | Исходник точного снимка, сохранён контракт нумерации строк runner |
| `prepare_markup_import` | Локальная подготовка после проверки полного инвентаря и решений |
| `apply_markup_import` | Точное подтверждение, одна попытка отправки, обратная проверка |

`fields=["*"]` сохраняет все поля Public API, в том числе `invariant` и
`checker_labels`. ГОСТ-фильтр выполняется сервером через `/afilters/apply`;
неподтверждённый фильтр никогда не заменяется выборкой всех предупреждений.
Если сервер не поддерживает требуемый ответ, операция заканчивается ошибкой,
а не выдуманными маркерами или исходниками.

Сохраняются адрес `http://127.0.0.1:8002/mcp`, имена инструментов, существующие
файлы задач, вход через окно приложения и явное подтверждение импорта.
HTTP слушает только loopback, проверяет локальный bearer и Host/Origin.
STDIO доступен через `app/start_svacer_stdio.py`.

## Авторизация и длительная работа

Файлы `.env` и сторонние credential-хранилища не читаются. Launcher передаёт
данные входа через окружение; Python забирает их из окружения и держит только
в памяти процесса. Повторный вход при 401 выполняется лишь для операций чтения,
с общей блокировкой обновления сессии. Запрос импорта автоматически не повторяется.
Пароль/токен, URL с учётными данными и тела ошибок сервера не выводятся.

TLS проверяется штатно. Для внутреннего удостоверяющего центра можно задать
`SVACER_CA_FILE` (путь к публичному CA-сертификату). Отключения проверки TLS нет.
При LDAP доступны `SVACER_AUTH_TYPE=ldap` и `SVACER_LDAP_SERVER`; эти параметры
не содержат пароль. Требуется доступ учётной записи к Public API, чтению
исходников и отдельно к экспорту/импорту разметки.

## Импорт без потери контроля

Подготовка разрешена только внутри `RESULTS` текущего приложения и не меняет
Svacer. Выбираются новые готовые решения; незавершённые, некорректные и уже
отправленные без изменений пропускаются и перечисляются в preview.
Проверяются полнота выбранных решений, метаданные маркеров, точный ГОСТ-фильтр,
независимая проверка Confirmed и отсутствие незавершённого исследования.
Сохранённый допустимый статус `Unclear` также сохраняется как `Unclear`:
коннектор не переопределяет вердикты. Новые `needs_context` импортировать нельзя.
Инварианты и locations берутся из текущего серверного экспорта, а не вычисляются
из имени файла. Противоречащие решения одного инварианта блокируют импорт.

**В Svacer разметка принадлежит инварианту во всей ветке**, в том числе его
вхождениям в других снимках. Preview явно указывает эту область действия.
Одинаковые инварианты объединяются; разные комментарии сохраняются.

Анализ других маркеров может продолжаться: состав партии фиксируется при
подготовке и не расширяется автоматически. Неготовое решение того же инварианта
блокирует его отправку, чтобы не разметить его косвенно.

Перед отправкой повторно проверяются хеши конфигурации, инвентаря и выбранных
решений, preview, payload и текущая
разметка сервера. Для конфликтов требуется отдельная фраза `FORCE IMPORT ...`.
`overwrite=last` запрещён. Непосредственно перед сетевой записью создаётся
`svacer-import-attempt.json` в эксклюзивном режиме с принудительной записью на диск.
При неизвестном исходе, в том числе тайм-ауте, повтор блокируется.

Успех — `completed_verified`: обратный экспорт подтвердил статусы, severity,
action и комментарии. Для успешной партии сохраняются preview, payload, попытка,
результат и квитанция в `svacer-import-batches/<nonce>/`; только после сохранения
квитанции снимается временная блокировка задачи. Следующие готовые решения можно
отправлять новой партией. Квитанции защищают от дублирования, включая перезапуск.
Изменённый комментарий или вердикт требует новой подготовки и подтверждения.
`completed_unverified` означает необходимость проверить
журнал операций Svacer вручную. Не удаляйте attempt-файл для слепого повтора.
В Public API нет условного импорта с ETag: стороннее изменение между последней
проверкой и `force` нельзя исключить атомарно; избегайте одновременной разметки
одной ветки несколькими людьми при принудительной перезаписи.

## Проверки и обновление

`app/tests/test_connector.py` использует синтетические данные и mock HTTP,
включая реальный MCP ASGI endpoint: нет рабочих паролей, внешних записей и
запусков модели. Проверяются фильтры, формат ответов, авторизация, preview,
положительные импорты, конфликты, изменение файлов, гонки и неизвестный сетевой исход.
`test_connector_process.py` дополнительно запускает настоящий процесс коннектора
по HTTP/STDIO с локальным тестовым REST-сервером, проверяя серию MCP-запросов
и сохранение авторизованного соединения между ними.
Эти тесты не заменяют приёмочный запуск после самостоятельного входа пользователя
в конкретную версию Svacer. Рабочий импорт в ходе замены не выполнялся.

Установка из чистого архива: создайте персональный файл из примера, запустите
`START.cmd -Menu`, пункт 6, затем пункт 3. При обновлении сперва дождитесь
завершения анализа и остановите старый MCP пунктом 8. Автоматическое переключение
активного процесса не выполняется. Старый локальный коннектор оставлен для отката,
но не нужен получателю нового архива.
