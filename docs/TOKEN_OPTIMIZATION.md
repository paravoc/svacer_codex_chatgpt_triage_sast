# Экономия токенов: оценка SoL-Pi для Svacer Triage

Проверено 21.09.2026. Изучена ревизия SoL-Pi
`bd005888b9b8a3fcdb511feb91fc27d3dfa8f2b1`.
Это оценка, а не включённый режим оптимизации. По решению пользователя
приложение остаётся на Codex. Pi не установлен, настройки Codex не изменены;
платные сравнения на маркерах не запускались.

## Совместимость

SoL-Pi — расширение для Pi со своими обработчиками контекста и инструментами,
не плагин для Codex. Его установка сама по себе не изменит расход нашего
`codex exec` или Codex Desktop. Поддерживаемый интерфейс расширения описан в
[документации совместимости SoL-Pi](https://github.com/NVlabs/SoL-Pi/blob/main/docs/compatibility.md).

В приложении `app/codex_run.py` запускает `codex exec --json --ephemeral`
через `build_codex_command` и `_run_one_codex_turn`. Python-процесс готовит
входные файлы и читает события, но не перехватывает контекст перед каждым
обращением модели. Поэтому полное воспроизведение ObservationPack потребовало
бы отдельной поддерживаемой точки интеграции, а не обработки уже записанного
`codex-events.jsonl`. Формат событий и usage описан в
[документации Codex](https://learn.chatgpt.com/docs/non-interactive-mode).

## Какие идеи подходят

Механизмы описаны в [репозитории SoL-Pi](https://github.com/NVlabs/SoL-Pi).
Оценка применимости ниже — вывод для нашего SAST-процесса, не обещание авторов.

| Механизм | Что делает | Решение для приложения |
| --- | --- | --- |
| ObservationPack | Заменяет повторяющийся большой вывод ссылкой на локальный оригинал с чтением по частям | Оценить похожую локальную выдачу исходников по диапазонам. Оригинал доступен всегда; модель всё равно может не запросить важный фрагмент |
| Action Fusion | Объединяет правку файла и последующую проверку в один вызов | Низкий приоритет: triage не должен менять анализируемый исходник. Подготовка исходников уже вынесена из модели |
| Evidence-Preserving Reducer | Дополнительная модель сокращает диагностические логи; цитаты проверяются | Не включать для рабочих данных без отдельного разрешения. Точность цитат не доказывает полноту выбранных доказательств |
| Online Context Compact | Суммирует контекст на границах подзадач | Не переносить первым: можно потерять ограничения, контрпримеры или незакрытые вопросы; суммаризация тоже расходует токены |

О передаче логов дополнительной модели и ограничениях проверки секретов прямо
предупреждает [SECURITY.md SoL-Pi](https://github.com/NVlabs/SoL-Pi/blob/main/SECURITY.md).
Локальный архив также содержит рабочие данные и требует тех же ограничений
доступа и хранения, что исходники. В этой проверке ничего такого не передавалось.

## Может ли ухудшиться результат

Да. В опубликованном сравнении Terminal-Bench 4 SoL-Pi решил 15 из 63 задач,
Pi и Codex — по 18. Это не SAST-тест и не прогноз качества конкретного маркера,
но уже не позволяет обещать экономию без ухудшений. Авторы отдельно отмечают
ориентацию на длинные сессии: выигрыш на коротких задачах может быть другим.
Источник: [результаты исследования](https://nvlabs.github.io/SoL-Pi/#results).

Для нас особенно опасны пропуск guard, одного caller, изменения состояния
или различий ревизии. Сохранение исходного файла на диске не гарантирует,
что модель прочитает его перед вердиктом. Экономия за счёт пропуска проверки
не считается улучшением.

## Что уже есть и что стоит проверить следующим

В `app/codex_run.py` уже есть подготовка точной ревизии и трасс до запуска
модели, локальный `source_catalog`, запрос недостающих файлов того же снимка,
инструкции для узкого поиска и запрет читать все прошлые решения. Результаты
проверяются на соответствие исходникам. Не следует выдавать эти существующие
механизмы за новую экономию SoL-Pi.

Первый кандидат для отдельного эксперимента — локальный поиск и чтение
исходников по диапазонам со следующими свойствами:

- ключ кэша включает snapshot, commit, путь и хеш содержимого;
- возвращаются точные строки, диапазон, признак неполного вывода и способ
  получить продолжение; пустая страница не означает отсутствие caller;
- полная трасса, исходники, проверки достижимости и независимая проверка
  Confirmed не удаляются; при недостатке данных остаётся `needs_context`;
- нет LLM-пересказа исходников и дополнительной отправки данных наружу;
- режим выключен по умолчанию и может быть отключён без изменения очереди
  и сохранённых вердиктов.

Это уменьшает лишнюю выдачу до попадания в контекст, но не удаляет уже
прочитанные сообщения из внутренней истории Codex. Изменение поведения чтения
тоже требует проверки: «без потерь байтов» не равно «без потерь качества».

## Как измерять, прежде чем включать

1. Зафиксировать одинаковые маркеры, ревизии, модель и reasoning effort.
   Сравнивать без исходных вердиктов в первичном контексте; эталон проверять
   вручную, а не считать существующую разметку автоматически правильной.
2. Запустить контроль и один изменённый механизм на одинаковом наборе,
   включив сложные callers, guards, зависимости и случаи нехватки исходников.
   Учитывать вариативность повторными запусками и отдельной отложенной выборкой.
3. Сравнить доказательства и ошибки классификации, особенно пропущенные
   реальные дефекты; отдельно считать незавершённые проверки и повторные попытки.
4. Учесть все проходы: основной анализ, дополнение контекста, исправление
   доказательств, проверку Confirmed. Сравнить `input_tokens`,
   `cached_input_tokens`, `output_tokens`, время и долю завершённых маркеров.
   Кэшированные входные токены не прибавлять к входным второй раз.
5. Процент недельного остатка — отдельный показатель: не превращать сокращение
   числа токенов в обещание такого же процента экономии подписки.

До такого сравнения численный выигрыш для Svacer Triage неизвестен.
Установка SoL-Pi в систему не нужна для описанного локального эксперимента.
